# ADR-0002: Capa de IA y modo sin red

- **Estado:** Aceptado
- **Fecha:** 2026-11-17
- **Contexto del proyecto:** Proyecto 2 de DAM (2º DAM), CLI para gestionar
  tareas asistidas por IA, con fines educativos.
- **Repositorio:** `cli-tareas`, rama `main`.

## 1. Problema que resuelve

La sesión 3 del enunciado exige que la CLI incorpore acciones que llamen a un
modelo (los mismos modelos del centro con los que trabaja OpenCode), con la
clave fuera del repositorio y un comportamiento seguro cuando no hay red o
falta la configuración: la CLI no debe revienta con un traceback, sino
explicarlo en una línea y seguir ofreciendo las acciones que no necesitan IA.

## 2. Decisión: endpoint compatible OpenAI configurable por variables de entorno

- La capa de IA (`src/cli_tareas/ia.py`) habla con cualquier endpoint
  compatible con la API de OpenAI (`/chat/completions`), que es el formato
  común de los modelos locales del centro (p. ej. ollama) y de OpenCode.
- **Ningún proveedor es obligatorio ni se fija en el código**: el endpoint y
  el modelo se configuran con variables de entorno, documentadas en
  `.env.example` sin valores reales:
  - `TAREAS_API_BASE`: URL base del servicio (obligatoria para usar IA).
  - `TAREAS_MODELO`: nombre del modelo (obligatorio para usar IA).
  - `TAREAS_API_KEY`: clave, solo si el servicio la exige (opcional).
  - `TAREAS_IA_TIMEOUT`: segundos de espera (opcional, por defecto 30).
- Si falta `TAREAS_API_BASE` o `TAREAS_MODELO`, las acciones de IA terminan
  con `IANoDisponibleError` («IA no configurada…») y código de salida 1,
  sin ningún intento de conexión. La integración queda preparada para
  configurarse cuando el centro facilite los datos de conexión.
- La acción `clasificar` reutiliza esta misma configuración y la misma
  infraestructura HTTP (`_solicitar_texto` en `ia.py`), sin fijar proveedor.

## 3. Privacidad: solo metadatos

- Las peticiones a la IA contienen **exclusivamente metadatos** de los
  elementos: nombre, tipo (fichero/carpeta), tamaño y fecha de modificación.
- **Nunca se envía el contenido de los ficheros** del usuario. `clasificar`
  solo procesa ficheros de primer nivel, ignora carpetas y limita el nombre
  enviado para reducir el riesgo de inyección de instrucciones mediante
  nombres de archivo.

## 4. Modo sin red y alternativa determinista

- Si no hay conexión, hay error HTTP (incluida autenticación 401/403) o la
  respuesta es inválida, la CLI muestra un mensaje de una línea sin secretos
  ni traceback, recuerda las alternativas (`--sin-ia` y las acciones sin IA
  `listar`, `contar`, `buscar`, `resumen`) y termina con código 1.
- La opción `--sin-ia` genera descripciones o clasificaciones deterministas
  por reglas a partir de los mismos metadatos, etiquetadas como
  «determinista»: es honesta, no simula ser IA y funciona sin configuración
  ni red. En `clasificar`, la extensión se asigna a `documentos`, `imágenes`,
  `código`, `datos`, `comprimidos` u `otros`; una categoría de IA desconocida
  también cae en `otros`, mientras que los errores de conexión, autenticación
  o las respuestas malformadas siguen siendo errores controlados.
- `--simular` se corta antes de la capa de IA: no hay llamadas de red, no
  consume créditos, no modifica archivos y no exige ninguna variable de
  entorno. En `clasificar`, `--simular --json` emite únicamente un JSON
  válido por stdout.

## 5. Sin dependencias nuevas

- La llamada HTTP usa `urllib.request` (librería estándar): `pyproject.toml`
  no añade dependencias de IA, lo que mantiene la instalación ligera y
  evita acoplarse a un SDK concreto.
- La salida JSON (`--json`) usa `json` estándar, limpia y sin colores.

## 6. Alternativas descartadas

| Alternativa | Inconvenientes |
|---|---|
| SDK oficial de un proveedor (p. ej. `openai`) | Añade dependencia y acopla la CLI a un proveedor concreto, que el centro aún no ha fijado. |
| Un proveedor cloud fijo con clave | Obliga a disponer de una clave desde el primer día; el enunciado pide los modelos locales del centro. |
| Enviar el contenido de los ficheros al modelo | Riesgo de privacidad inaceptable; contra la condición acordada. |
| Simular descripciones de IA cuando no hay red | Deshonesto; el enunciado exige explicar el problema, no fingir. |

## 7. Consecuencias

- Positivas: la CLI cumple «IA donde aporta», sin claves en el repo y sin
  depender de la IA para nada; modo sin red robusto y testeable (la red se
  simula en las pruebas con `monkeypatch`).
- Negativas: mientras el centro no facilite `TAREAS_API_BASE`/`TAREAS_MODELO`,
  las descripciones reales de IA no se pueden comprobar de punta a punta
  (solo con simulación en pruebas y con `--sin-ia`).
- La primera acción de IA es `describir` y la segunda es `clasificar`; ambas
  usan `max_ficheros` para limitar el coste y reutilizan `ia.py` sin cambios
  de arquitectura. `describir` conserva su firma pública, mensajes y salida.
